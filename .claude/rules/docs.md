# 저장소 문서 문체

`docs/` 아래 markdown의 기본 문체는 **개조식 · 명사형**이다. 개발 블로그에 어울리는 짧은 문장이 기준이고, 설명문을 길게 잇지 않는다.

## 종결

- 문장 종결은 **명사 · 명사형**(`~음` · `~함` · `~임` · 체언)이 기본 — "읽지 않음", "교체", "검사 대상에서 제외"
- 인과 · 판단을 잇는 문장 하나 정도는 짧은 서술문(`~다`) 허용. 명사형이 어색해지는 자리에서만 쓰고, 한 문단에 둘 이상 두지 않는다
- `~하는 것이다` · `~해야 했다` · `~게 됐다` 같은 늘어지는 종결은 쓰지 않는다

## 제목

- 제목은 **체언 종결**. `~했다` · `~한다`로 끝내지 않는다
- 나쁨 — `온보딩 소개 화면을 스크린 리더가 완료로 읽게 고쳤다`
- 좋음 — `온보딩 소개 화면을 스크린 리더가 완료로 읽도록 수정`

## 목록

- 항목은 `- **주제** — 설명` 형태. 끝에 마침표를 찍지 않는다
- 한 항목은 한 가지만 말한다. 두 가지면 항목을 나눈다

## 바꾸지 않는 것

**문체만 바꾸고 구조와 내용은 그대로 둔다.** 아래는 변환 대상이 아니다.

- 제목 계층 · 문단 순서 · 표 · 링크
- 코드 블록과 그 안의 주석
- 인용(`>`)한 원문 — 남의 문장은 그대로 옮긴다

## 이미 서술체인 문서

기록(`docs/records/`)은 전환이 끝났다. 나머지 문서는 아직 서술체이며, **그 문서를 크게 고칠 때 함께 전환한다.** 한 문서 안에서 두 문체를 섞지 않는다.
