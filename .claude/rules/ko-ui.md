# 사용자에게 보이는 화면

web과 mobile에 똑같이 적용된다. 상세 검수 절차는 별도이며, 여기에는 위반 여부를 바로 판정할 수 있는 것만 둔다.

## 언어

- UI 텍스트는 **한국어 존댓말**. 어미를 하나로 통일한다(`~했습니다` 또는 `~해요` 중 하나)
- **영어 AI 개발 용어를 화면에 노출하지 않는다.** `임베딩` · `프롬프트` · `추론` · `confidence` · `routing`은 내부 용어다
- 날짜 `2026. 8. 16.` / 금액 `12,000원` / 전화번호 `010-1234-5678`

## 화면에 남는 마지막 문장

**완료된 행동**이어야 한다 — "캘린더에 등록했습니다" · "지출로 저장했습니다".

화면에 넣지 않는 것: 신뢰도 점수 · 확률 · 모델 이름 · 처리 단계 로그 · "AI가 분석을 완료했습니다" 같은 과정 보고 · 축하 애니메이션. **분석이 끝난 화면은 성공 화면이 아니다.**

되돌릴 수 있는 실행에는 되돌리기를 붙이고, 되돌릴 수 없는 실행은 실행 전에 확인을 받는다. 둘 중 하나는 반드시 있어야 한다.

## 한국어 길이

한국어는 같은 뜻의 영어보다 길고 줄바꿈 규칙이 다르다.

- 버튼 라벨 · 탭 · 카드 제목에서 줄바꿈과 말줄임을 **매번 확인한다**
- web은 `word-break: keep-all`로 어절을 보호한다. 320px에서 가로 스크롤이 생기지 않아야 한다
- line-height를 줄이지 않는다. 한글은 1.5 미만이면 답답해진다

## 상태

화면을 만들 때 loading · empty · error · disabled를 함께 설계한다. 실패는 분명히 말하고 수동으로 할 방법을 준다. **이 네 상태를 위한 공용 컴포넌트는 아직 없다** — 처음 만드는 사람이 primitive로 올릴지 판단한다.

## 접근성

- web: semantic landmark · 전역 `:focus-visible` · 클릭 가능한 것은 `<button>`/`<a>`
- mobile: `accessibilityRole` · `accessibilityState`
- 공통: 최소 터치 타깃 **44px**
