# 제품 UX 검수 절차

`.claude/rules/ko-ui.md`가 무엇이 옳은지를 정한다. 이 문서는 **그것을 어떻게 확인하는지**를 다룬다.

기준 원문은 [product-principles.md](../../../../docs/product/product-principles.md).

## 결과 중심인가

화면의 문자열을 전부 뽑아서 본다.

```bash
grep -rn '["'"'"'>][가-힣]' apps/web/src apps/mobile/src | grep -v '\.spec\.'
```

문자열마다 묻는다.

- **이 문장이 사용자가 얻은 결과인가, 시스템이 한 일인가?** "분석했습니다"는 시스템, "캘린더에 등록했습니다"는 결과다
- 사용자가 이 문장을 보고 **다음에 뭘 할지** 아는가
- 이 문장이 없어도 화면이 이해되는가 → 그러면 뺀다

화면에 있으면 안 되는 것을 직접 찾는다.

```bash
grep -rniE '신뢰도|정확도|confidence|score|분석 (중|완료)|처리 중입니다|AI가' apps/web/src apps/mobile/src
```

`0.87`, `87%` 같은 숫자가 모델 출력에서 화면으로 새어 나가지 않는지도 본다.

## AI 개발 용어가 새지 않았는가

```bash
grep -rniE '임베딩|프롬프트|추론|모델|파이프라인|embedding|inference|routing|LLM' apps/web/src apps/mobile/src
```

주석과 변수명은 괜찮다. **화면에 렌더링되는 문자열만** 문제다. `metadata`, `aria-label`, `accessibilityLabel`도 화면 문자열로 친다.

## 한국어가 자연스러운가

- 어미가 한 화면 안에서 섞이지 않는가 (`~했습니다` / `~해요` 중 하나)
- 번역투가 아닌가. "당신의", "~되어집니다", "~에 대해" 같은 표현
- 명령형이 아니라 안내형인가. 버튼 라벨은 사용자가 하는 행동을 그대로 쓴다("저장", "취소")
- 같은 행동을 화면마다 다른 말로 부르지 않는가. "저장" 버튼이 만든 결과는 "저장했습니다"여야 한다

## 긴 한국어에서 깨지지 않는가

**읽어서 판단하지 않는다. 실제로 넣어본다.**

버튼·탭·카드 제목에 평소 문구의 2배 길이를 임시로 넣고 확인한다.

| 확인 지점       | 무엇이 깨지는가                                 |
| --------------- | ----------------------------------------------- |
| 버튼 라벨       | 줄바꿈되며 높이가 늘거나, 옆 버튼을 밀어낸다    |
| 카드 제목       | 말줄임 없이 넘치거나 카드 높이가 들쭉날쭉해진다 |
| 탭 · 칩         | 가로로 넘쳐 스크롤이 생긴다                     |
| 목록 한 줄 요약 | `numberOfLines` 없이 여러 줄로 번진다           |

web은 `word-break: keep-all`이 어절을 보호하므로 **긴 단어 하나가 컨테이너를 넘길 수 있다.** 320px에서 확인한다. mobile `Text`에는 넘칠 수 있는 곳에 `numberOfLines`를 준다.

## 과정이 아니라 결과를 보여주는가

- 사용자가 요청하지 않은 통계·차트·진행률을 보여주지 않는가
- 처리 단계를 나열하지 않는가. 사용자는 과정이 아니라 결과를 기다린다

## 토큰 밖의 값

[foundation.md](../../../../docs/design/foundation.md)가 토큰 값의 유일한 기준이다. 거기에 없는 값이 들어왔는지 훑는다.

```bash
# 정의 파일(global.css · tokens.ts) 자신은 제외한다
grep -rnE '#[0-9a-fA-F]{3,8}\b' apps/web/src apps/mobile/src --exclude=global.css --exclude=tokens.ts
grep -rn 'shadow-' apps/web/src --include='*.tsx' | grep -v 'shadow-card'
```

나온 것마다 **왜 토큰으로 안 되는지** 묻는다. 답하지 못하면 토큰을 쓰거나, foundation.md에 값을 추가하고 두 플랫폼 파일을 함께 고친다.

## loading · empty · error · confirmation

네 가지가 각각 **화면으로 존재하는지** 본다. 코드에 조건 분기만 있고 사용자가 볼 문구가 없으면 설계되지 않은 것이다.

| 상태             | 확인할 것                                                        |
| ---------------- | ---------------------------------------------------------------- |
| **loading**      | 무엇을 기다리는지 알 수 있는가. 체감 속도가 기능보다 앞선다      |
| **empty**        | 다음에 할 행동을 제안하는가. 그냥 "없습니다"로 끝나지 않는가     |
| **error**        | 무엇이 잘못됐고 어떻게 고치는지 말하는가. **수동 대안을 주는가** |
| **confirmation** | 무엇이 실제로 저장·전송되는지 보여주는가                         |

확인은 남발하지 않는다. 안전하고 되돌릴 수 있는 행동에 확인을 붙이면 사용자는 읽지 않고 누른다.

## Undo · Why · Confirmation

사용자가 일을 맡기려면 셋 중 맞는 것이 있어야 한다.

- **되돌릴 수 있는 실행** → 되돌리기가 성공 화면 안에 있는가 (설정 깊은 곳이 아니라)
- **되돌릴 수 없는 실행** → 실행 전에 확인을 받는가
- **제안한 행동** → 근거가 보이는가. 근거는 모델 설명이 아니라 **사용자가 확인 가능한 사실**이어야 한다 ("이미지에서 '8월 20일 19시 예약'을 찾았습니다")

**되돌리기와 사전 확인 중 하나는 반드시 있어야 한다.**

## 자동화

- 사용자가 켜지 않은 자동화가 동작하지 않는가
- 자동 실행 후 그 사실을 알리는가
- 송금 · 외부 발송 · 삭제가 자동화 대상에 들어가 있지 않은가
