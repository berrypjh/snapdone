# 포맷 검사가 변경된 파일만 봐서 5개를 영원히 놓치고 있었다

`nx format:check`는 base 대비 바뀐 파일만 검사한다. 한 번 어긋난 채 들어온 파일은 아무도 손대지 않는 한 검사 대상이 되지 않는다. 게이트를 `prettier --check .`로 바꿨다.

## 증상

포맷 게이트가 계속 통과하는데도 `tools/mcp/commit/`의 파일 5개는 포맷이 어긋난 상태로 남아 있었다.

## 원인

`nx format:check`의 대상은 **base 대비 변경된 파일**이다. 빠르게 돌기 위한 설계이고 Nx 쪽 버그가 아니다. 다만 그 전제는 "어긋난 파일은 언젠가 다시 수정된다"인데, 손대지 않는 폴더에서는 성립하지 않는다. 한 번 잘못 들어오면 그대로 굳는다.

## 고침

`pnpm format:check`를 `prettier --check .`로 바꿔 **저장소 전체**를 보게 했다. 빠른 검사 대신 빠짐없는 검사를 골랐다 — 포맷 검사는 원래 싸고, 커밋 시점에는 `lint-staged`가 staged 파일만 보며 이미 빠르게 돈다.

- 두 겹으로 나뉜다: 커밋 훅(`.husky/pre-commit` → `lint-staged`)은 지금 만지는 파일만, `pnpm verify`의 포맷 게이트는 저장소 전체
- 방치돼 있던 5개 파일도 같이 고쳤다

## 판단

대안은 "그 폴더를 한 번 포맷하고 `nx format:check`를 유지"였다. 택하지 않았다 — 같은 일이 다음 폴더에서 또 일어나고, 그때도 아무도 모른다. **검사가 놓치는 범위를 줄이는 쪽**이 한 번 고치고 마는 것보다 오래 간다.

## 근거

[품질 게이트 문서](../engineering/quality-gates.md)의 "`format`이 `nx format`이 아닌 이유"에 규칙으로 남겼다.
