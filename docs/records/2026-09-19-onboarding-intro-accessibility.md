# 온보딩 소개 화면을 스크린 리더가 완료로 읽게 고쳤다

예시 카드가 화면에 보이는 문구와 스크린 리더가 읽는 문구를 나누고, 화면이 열리면 제목으로 포커스를 보낸다. 보이는 것은 "캘린더 등록", 읽히는 것은 "캘린더 등록 완료"다.

## 상황

앱의 첫 화면인 온보딩 소개는 예시 카드 세 장으로 제품을 설명한다 — 영수증 · 6,500원 → 지출 기록 완료 같은 짝이다. 스크린 리더로 읽어 보니 네 가지가 어긋났다.

- 결과 문구가 "캘린더 등록" · "서울 맛집 저장"으로 끝났다. 눈으로는 체크 표시(✓)가 완료를 말하지만, 읽히는 문장에는 그 표시가 없다. [화면 규칙](../../.claude/rules/ko-ui.md)은 화면에 남는 마지막 문장이 **완료된 행동**이어야 한다고 못박는다
- 카드 라벨이 `Box` 안에 한 겹 더 둔 `View`에 붙어 있었다. 카드를 그리는 상자와 읽히는 상자가 달랐다
- 화면이 열려도 접근성 포커스가 제목으로 가지 않았다
- iOS에서 한국어 제목과 결과 문구가 단어 중간에서 끊겼다

## 고침

- 예시 데이터에 `spokenResult`를 더해 **보이는 문구와 읽히는 문구를 분리**했다. 카드 라벨은 `<source>, <detail>, <spokenResult>`이고, `spokenResult`는 모두 "… 완료"로 끝난다
- 접근성 라벨을 감싸던 `View`를 없애고 카드 `Box`가 직접 `accessible` 요소가 되게 했다. 카드 하나가 한 번에 읽힌다
- 화면이 뜨면 제목에 `AccessibilityInfo.sendAccessibilityEvent(..., 'focus')`로 포커스를 보낸다
- 제목과 결과 문구에 `lineBreakStrategyIOS="hangul-word"`를 줬다
- 같이 정돈한 것: 제목 `h2` → `h3`, 결과 문구 `body.largeStrong`, 체크 표시는 `text.success` 색, 카드 간격 `2xl` → `xl`

## 판단

읽히는 문장을 위해 **보이는 문장을 늘리지 않았다.** 화면에 "캘린더 등록 완료"라고 쓰면 카드가 길어지고 시각적으로는 체크 표시가 이미 같은 말을 한다. 스크린 리더에는 표시가 없으니 그쪽 문장만 완결시키는 편이 맞다고 봤다. 대신 두 문구가 갈라지므로 예시 데이터에 나란히 두어 한쪽만 고치는 일을 막았다.

## 검증

- 커밋 `7ed4e0b`. 바뀐 파일은 `apps/mobile/src/screens/OnboardingIntroScreen.tsx` 하나다
- **실제 스크린 리더로는 확인하지 못했다.** mobile 런타임을 검증할 수단이 AI 세션에 없다(시뮬레이터 · 기기 없음). 읽히는 순서와 완료 문구는 코드로만 확인했고, VoiceOver · TalkBack 확인은 기기에서 해야 한다
