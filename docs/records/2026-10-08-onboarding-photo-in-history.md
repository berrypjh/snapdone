# 온보딩 첫 사진을 온보딩을 마친 뒤 최근 처리 · 기록에 표시

온보딩 첫 사진은 DB에 저장되지만 최근 처리 · 기록 목록에서 빠져 있었음. 사용자가 직접 고른 사진을 처리한 결과인데 온보딩을 마치면 다시 열 길이 없었음. 앞으로 로그인 없이도 홈을 쓰게 할 예정이라, 목록에 넣는 조건을 화면이 아니라 서버 규칙으로 정함.

## 상황

- `GET /v1/processing-jobs`는 `origin = 'general'`인 작업만 돌려줌. 온보딩 첫 사진(`onboarding`)은 저장되지만 목록에는 없었음
- 그래서 온보딩을 마친 직후 홈은 항상 빈 홈이었고, 첫 결과는 작업 id를 모르면 다시 열 수 없었음
- 빼기로 한 이유를 적은 문서 · 기록은 없었음
- 지금은 홈과 기록이 온보딩을 마친 사용자에게만 열려서 목록이 곧 "온보딩 뒤"였음. 로그인 없이 쓰는 홈이 생기면 이 전제가 깨짐

## 판단

- **끝낸 일은 기록에 남김** — 성공 기준은 사용자가 하려던 일이 끝난 것이고, 첫 사진도 그 일임
- **온보딩을 마친 뒤에만 보임** — 온보딩 도중에는 목록에 넣지 않음. 어느 화면이 목록을 부르든 같은 규칙이 되도록 Go가 요청 세션의 온보딩 단계로 정함(`listedOrigins`). 작업 출처를 정하는 `jobOrigin`과 같은 자리
- **출처는 그대로 남김** — `origin` 컬럼과 값은 바꾸지 않음. 목록에서만 함께 보임
- **빈 홈은 정말 처리한 게 없을 때만** — 온보딩 직후 홈은 첫 사진이 있는 최근 처리 홈이 됨

## 반영

- Go `processing.Store.Recent` — 출처 목록을 받아 `origin = ANY(...)`로 읽음(이전 `RecentGeneral`)
- Go `httpserver.listedOrigins` — 온보딩 단계가 `complete`면 `onboarding` · `general`, 그 전이면 `general`
- web E2E fake API가 같은 규칙으로 목록을 돌려줌. 온보딩 E2E는 온보딩을 마친 홈에 첫 사진이 보이는지 확인
- Swagger 설명 · api rule · 아키텍처 문서 · DevHub 시나리오를 새 규칙으로 고침

## 검증

- Go 단위 테스트 — 온보딩 단계마다 목록에 넘기는 출처(`TestProcessingJobsOrigins`), 처리기가 받은 출처를 그대로 넘기는지
- Go DB 테스트 `TestRecentFiltersAndOrders` — 두 출처를 고르면 온보딩 작업이 최근 순 맨 앞에 들어가는지
- web E2E — 온보딩을 마친 홈의 최근 처리에 첫 사진 결과가 보이는지
